User Manual

How to run and present the city simulation and the Ground-N1 aircraft-to-ground demo: three windows, one shared simulation, five pads.

Covers: City simulation (home) · Ground-N1 launcher, pilot screen, ground control, live 3D window · Model hangar · Smart pad · Cockpit encounter · Integration lab

1. What this is

The project simulates an urban air mobility terminal with five landing pads (GN-01 to GN-05). It has two parts you can use on their own or together:

  • City simulation (home page). A fleet of UAMs (passenger aircraft) and UAVs (small drones) flies out from the pads, hovers over a city site, returns, lands, charges and redeploys. Use it to show fleet scale and traffic separation.
  • Ground-N1 demo. One UAM talks to the ground node. The pilot uses a cockpit screen, the ground-control team uses an operations screen, and a live 3D window shows the pad and the aircraft. Every instruction is a signed, verified datalink message and the ground automation explains its decisions.

2. Getting started

  1. Install Node.js (any recent version) and open a terminal in the project folder.
  2. Run npm install once. This downloads the pinned 3D library (three.js).
  3. Run npm start. It serves the project at http://localhost:8123.
  4. Open http://localhost:8123 in Chrome or Edge. The home page is the city simulation.
Check it works: run npm test. All suites should print PASS lines (city fleet, protocol, coordination, encounter and Ground-N1).

Requirements

  • A desktop browser with WebGL (Chrome, Edge, Firefox). The three Ground-N1 windows must be in the same browser so they can share one simulation.
  • For the two-screen demo use a display of at least 1280 × 720 per window. A second monitor is ideal for the live window.

3. Navigating between pages

Every page has the same bar across the top. The orange ← Home button (left) returns to the city simulation from any page. The other tabs are grouped as Ground-N1 (Launcher, Pilot, Ground control, Live 3D, Demo wall) and Explore (Overview, Cockpit encounter, Aircraft models, Smart pad, Integration lab). The current page is highlighted. On narrow windows the bar scrolls sideways.

At the right end of the bar, the pulsing ⓘ In simple words button opens a short plain-language explanation of the page you are on. Click Got it to close it; the button stops pulsing once you have used it.

Clicking a tab replaces the current window. During a Ground-N1 demo keep the Pilot, Ground and Live windows open; the simulation keeps running while at least one of them is open, and restarts if you close all of them.

4. City simulation (home)

Figure 1. City simulation: controls (top), 3D scene with the five pads, flight board and communications.

What you see

Aircraft depart a pad vertically, climb, fly to a city site, hover still for the mission, then return, wait for a free bay, land, charge (or swap the battery) and redeploy. Each UAM takes a whole pad. Each pad holds up to three UAVs, never mixed with a UAM.

The four counters show missions completed, separation advisories, aircraft airborne and aircraft waiting for a bay. Watch "waiting for a bay" rise when you raise demand with few pads free.

5. Ground-N1 demo: launcher and windows

Figure 2. Launcher (Ground-N1 › Launcher). Demo control panel on the right.

Starting the demo

  1. Open Ground-N1 › Launcher.
  2. Pick a Scenario, a Supervision mode and a Speed (½×, 1×, 2×, 4×).
  3. Click Start demo · open 3 windows (allow pop-ups). Live fills the screen; Pilot and Ground share the screen or go to a second display. Or click Demo wall to see all three on one display.

The panel shows the aircraft phase, simulated time, verified message count and how many windows are connected. Restart scenario resets everything; Pause freezes flight and timers; Autoplay lets the pilot press every recommended step by itself.

6. Ground-N1 walkthrough (step by step)

Use the Nominal arrival scenario at 1×. A full run takes about two and a half minutes. Progress shows in the bar under the pilot header.

#WhoActionWhat happens
1PilotConnectSigned HELLO; the node verifies the identity and replies with the session.
2PilotRequest landingThe automation checks all five pads, wind and battery. Occupied pads are rejected with the reason; it picks the nearest free pad.
3PilotAccept · read backThe read-back code is verified; the pad is locked and shows as reserved.
4PilotEngage approachThe aircraft flies the route, aligns over the pad and descends. Watch the live window.
5AutomaticTouchdownThe touchdown report and sink rate are verified. Rotors spool down.
6PilotPropulsion safeCharging starts (time-compressed for the demo).
7PilotRequest departureOffered once battery and weather allow; accept, then Engage departure.
8AutomaticClimb-outThe pad is released when the aircraft is clear; the session closes.

Reading a message

Each datalink entry shows kind, time, direction and text, plus chips: TX sent, RX delivered, ✓ SIG signature verified, ✓ ACK acknowledged. A rejected message is red with the reason.

Signing in the demo uses a keyed hash to show verification. It is not real cryptography.

7. Scenarios, supervision and tests

ScenarioWhat to show
Nominal arrivalThe full happy path.
Gusty wind holdThe request is held for wind. On the ground screen lower the wind slider; the automation reassesses and offers a clearance by itself.
Pad incursion drillDebris appears on the assigned pad on short final: clearance revoked, go-around, divert offer to another pad.
Low battery priorityBattery below reserve: the request is flagged priority and skips supervisor approval.
Link-loss drillThe datalink drops on approach: the aircraft goes around and holds. When the link returns, Connect again and re-request.

Things to try during any run

  • Switch to Supervised and approve a different pad than the one recommended.
  • On the ground screen, Report obstruction on the assigned pad mid-approach.
  • Click Send forged message and Replay last message: both are rejected and nothing changes.
  • Set the wind above the limit on final: the node orders a go-around.

Tips for presenting

  • Use Autoplay with the Demo wall for a hands-free loop; use 2× or 4× to shorten waits.
  • Put the Live window on the big screen and press H for a clean feed.

8. Other pages

Explore overview

A menu that explains each page in plain words (what it is, what to try, who it is for) plus a short glossary of terms such as UAM, clearance and go-around.

Cockpit encounter (guided)

The easiest way to understand the whole system. It runs its own private simulation, so it never disturbs a Ground-N1 demo running in other windows.

  • Coach (top): a progress strip, What is happening in simple words, and What to do next. Below it, the last decision made by the ground computer.
  • Left: a 3D view from the cockpit seat. Use the camera buttons (or keys 1 to 6) to switch to chase, pad, tower or orbit views.
  • Right: the Pilot screen, or the Ground team screen using the tabs. It is the same software as the Ground-N1 windows.
  • Cause a problem (bottom): Block the pad, Strong wind, Drop the radio link, Send a fake message, and A person approves landings (supervised mode). Press again to undo. The coach explains what the system does about each.
  • Top right: Watch it fly itself (autoplay), Speed (1×, 2×, 4×) and Restart. The earlier version is still available through the Classic version link.

Aircraft models

Turntable view of the Vahnim V6 air taxi (UAM) and S4 drone (UAV) with plain-language key facts. Choose Hover (rotors lifting), Cruise (the air taxi's wing carries it and its lift rotors stop; the drone tilts forward) or Parked. Drag to look around; scroll to zoom.

Smart pad

Interactive 3D pad concept. Click a part or the system list to highlight it; use Top view, Reset, auto-rotate and the exploded view.

Integration lab

Detailed exercise for equipped and visitor aircraft with operator review and failure cases (expiry, conflicts, link loss). It can also mirror city telemetry from another tab.

9. Troubleshooting and limits

ProblemFix
Page will not loadCheck npm start is running and use http://localhost:8123.
Windows do not openAllow pop-ups for the site, or open the pages from the tabs, or use the Demo wall.
Screens show different statesWindows must be in the same browser profile. Add ?local=1 to a page only if you want a private, unsynced copy.
Everything restartedClosing every Ground-N1 window ends the shared simulation. Keep at least one open.
3D scene is blankThe browser needs WebGL. Try Chrome or Edge with hardware acceleration on.
Buttons are greyed outActions only enable when valid. Follow the highlighted step, or read the hint under "Next step".
Limits. This is a simulation for demonstration. Flight dynamics are illustrative, not validated aerodynamics. Only one aircraft is simulated in Ground-N1; other pads show parked aircraft. Charging is time-compressed. The pilot screen is a software concept, not a certified flight instrument. Registry, read-back and message signing are demonstrations. No aviation regulatory compliance is claimed.

Tuning notes for developers (pad positions, limits, scenarios, aircraft specifications, colours) are in the project README under "Tuning cheat-sheet".
